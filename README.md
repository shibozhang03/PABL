# Proximal Angle-Based Learning for Multiple Treatments

Code for the simulations and MIMIC-IV application reported in the manuscript and supplement.

## Installation

Use Python 3.12 and the package versions in `requirements.txt`. The analysis environment used Linux and PyTorch 2.9.1 with CUDA 12.8.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

For CUDA 12.8, install the matching PyTorch build:

```bash
python -m pip install torch==2.9.1 --index-url https://download.pytorch.org/whl/cu128
```

Run all commands from the repository root. Replace `cuda` with `cpu` to use a CPU. The reference GPU was an NVIDIA RTX 4090 with 24 GiB of memory. Full simulations may take several days, and application analyses may take hours. Runtime and numerical results can vary across environments.

## Simulations

Run in this order:

```bash
python run_simulation.py --outcome continuous --device cuda
python run_simulation.py --outcome survival --device cuda
python make_figures.py --part simulation
```

The simulations use linear and nonlinear treatment interactions for continuous outcomes and linear interactions for Weibull AFT survival outcomes. Training sample sizes are 2,000 and 5,000. In `U0`, treatment effects do not depend on the unmeasured confounder; in `U1`, they do. Each setting uses 100 replications and 500,000 test observations per replication. Survival probabilities are evaluated at times 0.75, 1.00, and 1.25.

Simulation data are generated by `pabl/dgp.py` and `pabl/dgp_survival.py`, with seeds assigned in `run_simulation.py`.

To run a subset:

```bash
python run_simulation.py --outcome continuous --n 2000 --rep-start 0 --rep-stop 10 --device cuda
```

This example runs replications 0 through 9 for each selected setting. Rerunning the command skips replications with saved results. Use the same software environment throughout. Plotting requires all 100 replications of every continuous and survival setting.

## MIMIC-IV application

The application requires authorized access to [MIMIC-IV 3.1](https://physionet.org/content/mimiciv/3.1/); patient data are not included. Follow the PhysioNet access instructions, then load the official hospital tables into PostgreSQL under the `mimiciv_hosp` schema.

Use PostgreSQL 14 with `psql` available in `PATH`. Required tables are `admissions`, `patients`, `emar`, `prescriptions`, `microbiologyevents`, `labevents`, and `transfers`. Configure database authentication outside the repository. The database user needs permission to read these tables and create temporary tables.

```bash
python run_real_data.py --database mimiciv31 --device cuda
python make_figures.py --part real-data
```

Replace `mimiciv31` with your database name. Cohort construction and preprocessing are in `real_data/cohort.sql` and `real_data/preprocessing.py`. The analysis checks for 11,944 patients after the support restriction and uses five folds with seed `20260813`.

The analyses cover DAOH28 and survival at 90 days without censoring or with simulated censoring. To run one, add `--outcome daoh28`, `--outcome survival90`, or `--outcome censored` to the analysis command. The agreement figure requires all three analyses.

`real_data/censoring.py` defines the simulated censoring mechanism, with seed `20260820`.

## Outputs and manuscript results

All outputs are written under `results/`.

| Result | Output |
| --- | --- |
| Simulation policy values | `simulation/<setting>/rep_000.csv` through `rep_099.csv`; combined tables in `figures/<setting>/values.csv` |
| Main continuous comparison | `figures/continuous_*_5000/boxplot_true_val.png` |
| Supplementary continuous comparison | `figures/continuous_*_2000/boxplot_true_val.png` |
| Main survival comparison | `figures/survival_linear_U*_5000/boxplot_true_val_t1.png` |
| Supplementary survival comparisons | Remaining survival panels under `figures/survival_linear_U*_<n>/`, with suffixes `t0p75`, `t1`, or `t1p25` |
| Application tables | `real_data/daoh28.csv`, `real_data/survival90.csv`, and `real_data/censored.csv` |
| Application agreement values and figure | `real_data/*_agreement.json` and `figures/blood_culture_recommendation_agreement.pdf` |

Application tables report policy values, standard errors, and treatment recommendation percentages. The JSON files contain pairwise agreement percentages used to draw the PDF. Only aggregate application results are saved.

## Code organization

- `pabl/`: shared estimators, simulation data generation, tuning, and plotting.
- `real_data/`: cohort SQL, preprocessing, censoring, and application estimators.
